# คู่มือการ Deploy ระบบ EquipTrack ขึ้น AWS EC2 (ฉบับอธิบายละเอียดทุกคำสั่ง)

คู่มือนี้จัดทำขึ้นเพื่ออธิบายว่าแต่ละคำสั่งในการนำระบบขึ้นเซิร์ฟเวอร์ (Host) ทำหน้าที่อะไรบ้าง เพื่อให้คุณเข้าใจกระบวนการทั้งหมดตั้งแต่ต้นจนจบ (รวมถึงการรองรับ EIP และ HTTPS)

---

## ส่วนที่ 1: การเตรียมไฟล์จากเครื่อง Windows (คอมพิวเตอร์ของคุณ)

### 1. การเคลียร์สิทธิ์ไฟล์กุญแจ (.pem)
```powershell
icacls "C:\Users\ASUS\Downloads\AssetManagement.pem" /inheritance:r /grant:r "$($env:USERNAME):(R)"
```
**ทำไมต้องรัน:** ระบบความปลอดภัยของ Windows และโปรแกรม SSH บังคับว่า "ไฟล์กุญแจต้องถูกอ่านได้โดยเจ้าของเครื่องเพียงคนเดียวเท่านั้น" หากปล่อยให้สิทธิ์เปิดกว้าง โปรแกรม SSH จะปฏิเสธการเชื่อมต่อ คำสั่งนี้คือการลบสิทธิ์คนอื่นออก (inheritance:r) และให้สิทธิ์เฉพาะคุณ (grant:r)

### 2. การบีบอัดไฟล์ Source Code
```powershell
tar -cf project.tar --exclude=node_modules --exclude=.next --exclude=.git .
```
**ทำไมต้องรัน:** แทนที่จะอัปโหลดไฟล์ไปทีละไฟล์ซึ่งช้ามาก เราใช้คำสั่ง `tar` เพื่อมัดรวมโปรเจกต์เป็นก้อนเดียว (`project.tar`) โดยสั่ง `--exclude` เพื่อ **ไม่เอา** โฟลเดอร์ที่หนักและไม่จำเป็น (เช่น node_modules) เพราะเราจะไปโหลดใหม่บนเซิร์ฟเวอร์แทน

### 3. การอัปโหลดไฟล์ขึ้น EC2
```powershell
scp -i "C:\Users\ASUS\Downloads\AssetManagement.pem" -o StrictHostKeyChecking=no project.tar ubuntu@<ใส่_IP>:~/
```
**ทำไมต้องรัน:** `scp` (Secure Copy) คือคำสั่งสำหรับส่งไฟล์ผ่านระบบเครือข่ายอย่างปลอดภัย โดยเรายื่นกุญแจ (`-i`) ให้ระบบตรวจสอบ และส่งไฟล์ `project.tar` ไปวางไว้ที่หน้าแรก (`~/`) ของ user `ubuntu` บนเซิร์ฟเวอร์

### 4. การรีโมทเข้าเซิร์ฟเวอร์
```powershell
ssh -i "C:\Users\ASUS\Downloads\AssetManagement.pem" -o StrictHostKeyChecking=no ubuntu@<ใส่_IP>
```
**ทำไมต้องรัน:** เป็นการล็อกอินเข้าเซิร์ฟเวอร์เพื่อเข้าไปสั่งงานคอมพิวเตอร์ EC2 เครื่องนั้น

## ส่วนที่ 2: การตั้งค่าบนเซิร์ฟเวอร์ EC2 (Ubuntu)

### 1. ติดตั้ง Docker
```bash
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
```
**ทำไมต้องรัน:** เซิร์ฟเวอร์ที่เพิ่งสร้างใหม่จะเป็นเครื่องเปล่าๆ เราใช้คำสั่งนี้ดาวน์โหลดสคริปต์ติดตั้ง Docker (ตัวจัดการ Container ที่เราจะใช้รันระบบ) และสั่งรันติดตั้งแบบอัตโนมัติ

### 2. แตกไฟล์โปรเจกต์
```bash
mkdir -p ~/app
tar -xf ~/project.tar -C ~/app
cd ~/app
```
**ทำไมต้องรัน:** สร้างโฟลเดอร์ชื่อ `app` จากนั้นแตกไฟล์ (`tar -xf`) ที่เราเพิ่งอัปโหลดขึ้นมาเข้าไปไว้ในนั้น แล้วย้ายตัวเองเข้าไปทำงานในโฟลเดอร์นั้น (`cd`)

### 3. อัปเดตที่อยู่ของระบบ (URL/IP)
```bash
sed -i 's|http://localhost:3000|https://<ชื่อโดเมน>|g' .env
```
**ทำไมต้องรัน:** `sed` คือเครื่องมือค้นหาและแทนที่คำในไฟล์ (Find & Replace) เราใช้มันเปลี่ยนคำว่า `localhost:3000` ในไฟล์ตั้งค่า (`.env`) ให้กลายเป็น IP (หรือ Domain Name) จริง เพื่อให้เวลาระบบสร้าง QR Code หรือทำลิงก์ มันจะชี้มาที่เซิร์ฟเวอร์ได้อย่างถูกต้อง

### 4. สั่งรันระบบทั้งหมด
```bash
sudo docker compose up -d --build
```
**ทำไมต้องรัน:** เป็นคำสั่งไม้ตายของ Docker 
- `--build` หมายถึงให้มันอ่านไฟล์ `Dockerfile` แล้วสร้างระบบขึ้นมาใหม่ (ติดตั้งโค้ด)
- `-d` (Detached mode) หมายถึงให้มันรันระบบทิ้งไว้เบื้องหลัง (Background) ต่อให้เราปิดหน้าต่างสีดำ (Terminal) ไปแล้ว เว็บเราก็ยังทำงานต่อไปไม่ดับ

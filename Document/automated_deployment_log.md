## 💻 ส่วนที่ 1: คำสั่งที่รันบนเครื่อง Windows (Local)

AI ได้รันคำสั่งเหล่านี้ผ่าน PowerShell ของเครื่องคุณ เพื่อเตรียมไฟล์และส่งขึ้นเซิร์ฟเวอร์:

**1. แก้ไขสิทธิ์ไฟล์กุญแจ:**
```powershell
icacls "C:\Users\ASUS\Downloads\AssetManagement.pem" /inheritance:r /grant:r "$($env:USERNAME):(R)"
```
* **ทำไปทำไม:** Windows จะไม่อนุญาตให้ใช้ไฟล์ `.pem` ล็อกอินเข้าเซิร์ฟเวอร์ถ้าสิทธิ์ไฟล์เปิดกว้างเกินไป คำสั่งนี้เป็นการจำกัดสิทธิ์ให้คุณอ่านไฟล์ได้คนเดียว (SSH ถึงจะยอมให้ผ่าน)

**2. บีบอัดโค้ดโปรเจกต์:**
```powershell
tar -cf project.tar --exclude=node_modules --exclude=.next --exclude=.git .
```
* **ทำไปทำไม:** เพื่อรวบรวมไฟล์ทั้งหมดให้เป็นก้อนเดียว (`project.tar`) โดยสั่ง `--exclude` ข้ามโฟลเดอร์หนักๆ อย่าง `node_modules` ไป (เพราะเดี๋ยวเซิร์ฟเวอร์จะไปดาวน์โหลดใหม่เอง) ทำให้ไฟล์เบาและส่งเร็วขึ้นมาก

**3. สร้างไฟล์ Script อัตโนมัติ:**
* AI ทำการสร้างไฟล์ชื่อ `remote_deploy.sh` เอาไว้ เพื่อเอาไปรันคำสั่งติดตั้งบนเซิร์ฟเวอร์รวดเดียว (ดูเนื้อหาในส่วนที่ 2)

**4. อัปโหลดไฟล์ขึ้น EC2:**
```powershell
scp -i "C:\Users\ASUS\Downloads\AssetManagement.pem" -o StrictHostKeyChecking=no project.tar remote_deploy.sh ubuntu@43.211.59.105:~/
```
* **ทำไปทำไม:** `scp` คือคำสั่งก๊อปปี้ไฟล์ข้ามเครื่อง เราส่งทั้ง `project.tar` และสคริปต์ `remote_deploy.sh` ไปยัง EC2

**5. สั่งรันสคริปต์บน EC2:**
```powershell
ssh -i "C:\Users\ASUS\Downloads\AssetManagement.pem" -o StrictHostKeyChecking=no ubuntu@43.211.59.105 "bash ~/remote_deploy.sh"
```
* **ทำไปทำไม:** รีโมทเข้าไปสั่งให้เซิร์ฟเวอร์เริ่มทำงานตามสคริปต์ที่เราส่งไป

## ☁️ ส่วนที่ 2: คำสั่งที่รันบนเซิร์ฟเวอร์ (Ubuntu EC2)

เมื่อคำสั่งข้อ 5 ด้านบนทำงาน มันจะไปกระตุ้นให้เซิร์ฟเวอร์รันชุดคำสั่งในไฟล์ `remote_deploy.sh` ดังนี้:

**1. ติดตั้ง Docker:**
```bash
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker ubuntu
```
* **ทำไปทำไม:** ดาวน์โหลดตัวติดตั้ง Docker และติดตั้งลงเครื่อง เพื่อใช้เป็นเครื่องมือหลักในการรันระบบ (รันเว็บ, รันฐานข้อมูล)

**2. แตกไฟล์โปรเจกต์:**
```bash
mkdir -p ~/app
tar -xf ~/project.tar -C ~/app
cd ~/app
```
* **ทำไปทำไม:** สร้างโฟลเดอร์ชื่อ `app` และแตกไฟล์โค้ดที่เราบีบอัดไว้ออกมาเพื่อเตรียมพร้อม

**3. อัปเดต IP ให้ระบบ:**
```bash
sed -i 's|http://localhost:3000|http://43.211.59.105|g' .env
```
* **ทำไปทำไม:** ค้นหาคำว่า `localhost:3000` ในไฟล์ตั้งค่า และเปลี่ยนเป็น IP จริง (43.211.59.105) เพื่อให้ระบบส่งอีเมล หรือระบบ QR Code อ้างอิง URL ได้อย่างถูกต้อง

**4. รันระบบ (ปัญหาที่พบและวิธีแก้):**

🔴 **ปัญหาที่พบ:** 
ตอนแรก AI ใช้คำสั่ง `sudo docker compose up -d --build` แต่ Docker เวอร์ชั่นล่าสุดบน Ubuntu 26.04 แจ้ง Error กลับมาว่า `unknown flag: --build` (มันไม่รู้จักคำสั่งห้อยท้ายนี้ในรูปแบบที่พิมพ์ไป)

🟢 **วิธีที่ AI แก้ปัญหา (รันอัตโนมัติรอบสอง):** 
AI ตรวจจับ Error ได้ จึงเปลี่ยนวิธีการพิมพ์คำสั่งให้แยกกันชัดเจน เพื่อความชัวร์ 100% โดยรัน 2 คำสั่งนี้แทน:

```bash
# 1. สั่ง Build Image ก่อนให้เสร็จ
sudo docker compose build 

# 2. สั่งรันระบบที่ Build เสร็จแล้วขึ้นมาทำงานเบื้องหลัง
sudo docker compose up -d
```
* **ผลลัพธ์:** สามารถสร้าง Docker Image ของ Next.js ได้สำเร็จสมบูรณ์ และรัน Container ขึ้นมาให้บริการเว็บไซต์ที่พอร์ต 80 ได้เรียบร้อยครับ! 🎉

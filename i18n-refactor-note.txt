====================================================
  i18n Refactor — แบบเดิม vs แบบใหม่
====================================================

----------------------------------------------------
  แบบเดิม (ก่อน Refactor)
----------------------------------------------------

โครงสร้าง:
  src/lib/i18n.tsx   — ไฟล์เดียว 1,970 บรรทัด

ปัญหา:

1. ไฟล์ใหญ่เกินไป
   - Logic ของ Provider จริงๆ แค่ ~70 บรรทัด
   - ที่เหลือ ~1,900 บรรทัด คือ translation text ของ 3 ภาษา
     ยัดรวมกันในไฟล์เดียว ทำให้เปิดไฟล์แล้วหาอะไรยาก

2. แก้ไข translation ลำบาก
   - อยากแก้แค่คำภาษาญี่ปุ่นคำเดียว ต้องเลื่อนหาในไฟล์ 1,970 บรรทัด
   - ง่ายต่อการแก้ผิดภาษา เช่น ตั้งใจจะแก้ EN แต่ไปแก้ TH โดยไม่รู้ตัว

3. Git conflict เยอะ
   - ถ้ามีคนแก้ภาษาไทย กับอีกคนแก้ภาษาอังกฤษ พร้อมกัน
     จะ conflict กันในไฟล์เดียวกัน ทั้งที่ไม่ได้แก้ส่วนเดียวกันเลย

4. อ่าน code ยาก
   - เปิดไฟล์มาเจอ translation text ยาวมากก่อน
     กว่าจะเลื่อนไปเจอ logic ของ Provider ต้องเลื่อนไปท้ายไฟล์

----------------------------------------------------
  แบบใหม่ (หลัง Refactor)
----------------------------------------------------

โครงสร้าง:
  src/lib/i18n/
    ├── index.tsx          — 95 บรรทัด (Provider, useI18n, t function)
    └── locales/
        ├── th.ts          — เฉพาะภาษาไทย
        ├── en.ts          — เฉพาะภาษาอังกฤษ
        └── ja.ts          — เฉพาะภาษาญี่ปุ่น

ข้อดี:

1. แยก concern ชัดเจน
   - Logic อยู่ที่ index.tsx — สั้น อ่านง่าย
   - Translation แต่ละภาษาอยู่คนละไฟล์ — หาง่าย แก้ง่าย

2. แก้ไข translation ง่ายขึ้นมาก
   - อยากแก้ภาษาญี่ปุ่น เปิดแค่ ja.ts ไฟล์เดียว
   - ไม่มีทางไปแก้ผิดภาษาโดยไม่ตั้งใจ

3. Git conflict น้อยลง
   - แก้ภาษาไทย → แก้ th.ts
   - แก้ภาษาอังกฤษ → แก้ en.ts
   - คนละไฟล์ ไม่ conflict กัน

4. เพิ่มภาษาใหม่ง่าย
   - สร้างไฟล์ใหม่ เช่น locales/zh.ts
   - import เข้า index.tsx เพิ่มบรรทัดเดียว
   - ไม่ต้องไปแทรกในไฟล์ใหญ่

5. ไม่ต้องแก้ import เดิม
   - ทุกที่ที่เขียน import { useI18n } from "@/lib/i18n"
     ยังใช้งานได้เหมือนเดิม เพราะ index.tsx export ทุกอย่างเหมือนเดิม

----------------------------------------------------
  สรุป
----------------------------------------------------

- Logic เดิมไม่ได้เปลี่ยน — แค่ย้ายจัดโครงสร้างให้ดีขึ้น
- ไม่มี breaking change — import path เดิมใช้ได้หมด
- ดูแลรักษาง่ายขึ้น โดยเฉพาะเวลาเพิ่ม/แก้ translation
